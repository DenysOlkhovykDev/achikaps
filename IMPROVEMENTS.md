# Журнал покращень

Дата: 7 серпня 2026 року

## Що зроблено

### Новий ігровий контент

- Додано нову анімовану будівлю **Windmill**.
- Windmill виробляє ресурс **Battery**, який раніше існував у коді, але не мав
  джерела виробництва.
- Windmill додано до меню будівництва, реєстру будівель, стартової сцени та
  демонстраційного сценарію.
- Battery додано до рецепта Engine. Тепер існує завершений ігровий ланцюжок
  `Windmill → Battery → Engine`.
- Меню будівництва розширено з восьми до одинадцяти споруд.
- Відкрито для будівництва декоративні House і Junkyard, які вже мали моделі та
  рецепти, але були відсутні в меню; назву `Junkuard` виправлено на `Junkyard`.

### Керування та відображення

- Підключено керування камерою через `WASD` і клавіші зі стрілками. Обробники
  клавіш уже були в проєкті, але раніше не впливали на гру.
- Додано скидання натиснутих клавіш при втраті фокусу, щоб керування не
  «залипало» після перемикання вікон.
- Джойстик тепер має справжній аналоговий газ замість миттєвої повної швидкості,
  а швидкість повороту більше не залежить від FPS.
- Canvas адаптується до розміру вікна, зберігаючи квадратні пропорції.
- Додано viewport/meta description, нейтральне тло сторінки та базові
  accessibility-атрибути для canvas.

### Ігрова логіка

- Виправлено створення звичайних завдань: раніше функція повертала один об’єкт
  `Task`, але в чергу додавала інший.
- Виправлено підрахунок заявок для рецептів із кількома однаковими ресурсами.
- При створенні delivery-завдань враховуються ресурси, які вже заплановані до
  доставки, тому однакові заявки не дублюються без потреби.
- Для однієї будівлі більше не накопичуються дублікати однакових production
  task-ів під час серійного виготовлення ресурсів.
- Розрахунок вільного місця тепер використовує фактичну кількість відсутніх
  інгредієнтів.
- Dashboard оцінює delivery/building task за реальною довжиною маршруту
  `worker → resource → target`, а не за приблизною формулою, тому робітники
  обирають ближчі завдання точніше.
- Джерело ресурсу також вибирається за повним маршрутом через ціль, а не лише за
  близькістю складу до робітника.
- Резервування ресурсів переведено з нестабільного індексу масиву на посилання
  на конкретний об’єкт. Це усуває помилки при одночасній роботі кількох
  робітників.
- Виробництво й нові заявки рахують лише незарезервовані ресурси, тому factory
  більше не може спожити вантаж, за яким уже прямує інший робітник.
- Ресурс перестає бути зарезервованим одразу після забору зі складу і знову
  доступний для наступних виробничих циклів після доставки.
- Якщо склад цілі заповнився до прибуття, робітник тепер зберігає вантаж і
  повторює доставку після звільнення місця; раніше ресурс безповоротно зникав.
- Невдалий або завершений blueprint тепер централізовано очищає свої task-и,
  Pixi-лінії та listener; робітники більше не отримують заявки від уже видаленої
  споруди.

### Стабільність UI

- Усунено витік Pixi-об’єктів у фінальному повідомленні: overlay більше не
  створює новий `Text` на кожному кадрі, а повторно використовує один екземпляр.
- Стан меню тепер гарантовано скидається при його примусовому закритті.
- Dashed road для blueprint безпечно обробляє нульову відстань і більше не
  створює координати `NaN`, якщо креслення поставити точно на вихідну платформу.

### TypeScript і підтримка проєкту

- Додано типізовану властивість `window.app`, прибрано відповідні `any` у коді
  гри та тестовій інфраструктурі.
- Професії робітників і callback-и tutorial-системи отримали конкретні union/
  function types замість довільних рядків і загального `Function`.
- Додано єдиний union `ResourceType` для рецептів, ресурсів, task-ів і сценаріїв;
  помилки в назвах ресурсів тепер виявляються під час компіляції.
- Реєстр будівель формує типи `BuildingType`/`BuildingKind`; меню, blueprint-и та
  сценарії більше не приймають довільні назви або прихований fallback на
  Platform.
- Поле рецептів `ingridients` виправлено на коректне `ingredients` у всій
  кодовій базі.
- Виправлено застарілі помилки в іменах ключових API: `buildingParameters`,
  `resources`, `getPossibleTaskWithHighestPriority`, `blueprintToBuilding` та
  `createTestBuildings`.
- Додано `npm run typecheck` і `npm run check`.
- Увімкнено `skipLibCheck`, щоб сувора перевірка коду проєкту не падала через
  конфлікт декларацій WebGPU між PixiJS і TypeScript 6.
- Спільні кроки Playwright-сценаріїв винесено до одного helper, щоб не дублювати
  відкриття гри, очікування canvas і створення snapshot.
- README розширено описом gameplay, керування, команд і структури проєкту.

## Перевірка

- `npm run typecheck` — проходить.
- `npm run build` — проходить.
- `git diff --check` — не знаходить помилок whitespace.
- Локальна гра перевірена у браузері на desktop viewport і на вузькому
  `390×844`: Windmill, меню з 11 споруд та responsive canvas відображаються
  коректно.
- У браузерній консолі під час перевірки немає warning/error повідомлень.

Visual snapshots навмисно не використовувались як обмеження для нового
контенту: Windmill і зміна рецепта Engine закономірно змінюють еталонний вигляд
частини сцен.
